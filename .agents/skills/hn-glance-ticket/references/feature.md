# Feature Ticket

Use for new or intentionally changed user-visible behavior.

Suggested existing label: `enhancement`.

```markdown
### Outcome

<What should become possible or materially better for the reader?>

### Context

<Why this matters; include affected routes or browsing flow.>

### Scope

- <In-scope behavior>

### Non-goals

- <Explicit exclusions when ambiguity is likely>

### Acceptance Criteria

- [ ] <Observable product behavior>
- [ ] <Relevant responsive, accessibility, caching, or failure-state behavior>

### Implementation Notes

<Optional constraints, likely modules, compatibility requirements, or prior art.>

### Validation

<Browser scenarios and automated checks that prove the outcome.>

### Definition of Done

<Only relevant shared checklist items.>
```

Cover loading, empty, error, dark-mode, and mobile states when materially
affected. Preserve screenshot dominance and the distinct story/source
navigation actions.
