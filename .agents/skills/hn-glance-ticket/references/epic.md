# Epic Ticket

Use only for a coherent outcome that requires multiple independently
deliverable child tickets.

```markdown
### Outcome

<The coherent result this Epic should deliver.>

### Context

<Why the outcome matters and why it needs multiple tickets.>

### In Scope

- <Capability or workstream>

### Out of Scope

- <Explicit boundary>

### Success Signals

- <Observable product, reliability, performance, or operational signal>

### Sub-issues

<Use native sub-issues; include a short ordering note only when sequence matters.>

### Risks and Dependencies

<Use native blocked-by relationships and summarize material risk.>

### Exit Criteria

- [ ] Required child tickets are complete or explicitly removed from scope.
- [ ] Success signals are verified.
- [ ] Remaining follow-up work is recorded separately.
```

Epic effort may be `XL`; each implementation child should normally be `L` or
smaller. Do not use an Epic as one large implementation checklist.
